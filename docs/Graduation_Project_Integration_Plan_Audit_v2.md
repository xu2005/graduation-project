## 1. 总体评价

**原报告可以作为开发依据，资源分配和主体架构不需要推翻；但它目前是整合规划，尚不足以直接充当接口行为规范。**需要优先补清“结果只能消费一次”“STOP 何时算完成”“串口缓冲何时可以改写”这几个约束。最明显的低估是 DHT11 与异步串口输入的冲突；最明显的过度要求是把结果读取一概描述为必须新增原子接口。

**资源审计通过，前提明确如下：**

| 检查项 | 审计判断 |
|---|---|
| APB1 Timer clock | HCLK=72 MHz、APB1 分频=2 时，PCLK1=36 MHz，而 TIM2/TIM3 内核时钟均为 72 MHz。原报告正确。APB 分频为 1 时才不倍频，不能把“总是乘 2”写进驱动。 |
| TIM2 输入捕获 | 内部时钟、向上计数、PSC=71、ARR=65535，得到 1 µs 分辨率和 65.536 ms 回绕周期。CH1 选 Direct TI、捕获分频 DIV1、初始上升沿，沿用现有软件换沿算法合理；当前最大有效脉宽 23.2 ms 和正常服务下约 40 ms 超时均小于计数周期。 |

## 2. 必须修正的问题

**2.1 HC 结果交接必须规定“处理后、消费一次、再触发”（高）。**

依据：`HC_SR04_ECHO/Drivers/HC_SR04/hcsr04.c:174-197` 先发布待滤波样本，再置 ready；`296-305` 的 Process 先处理样本；`269-294` 的 Trigger 只检查空闲，不检查上一结果是否已被应用消费。

原报告指出的 ready/滤波竞态确实存在：Process 返回后 ISR 才完成，此时 ready 已置位而滤波值还没有更新。除此之外，还需防止 ready 持续为 1 时重复累计同一结果，以及“驱动空闲但结果尚未消费”时过早启动下一次测量。`measurement_active==0` 单独不足以证明可以换角或重触发。

最低修改量方案如下，不必重做驱动：

- 仅 Scan 在主循环触发；接受一次触发后保存本次角度，并只允许一个未结算测量。
- 检查到本次 ready 后再调用 Process，随后读取结果、登记“已消费”，立即离开本次 WAIT_ECHO/COLLECT 路径；失败也只结算一次。
- 上次结果消费完后才允许下一次 Trigger；换角前才能 FilterReset。该函数保持“只清滤波窗口”的职责，不必改成取消测量。
- 对第三个有效样本，应先判断“已集齐 3 个”，再判断“尝试次数已到 5”；否则第五次恰好成功会被错误判失败。每次重试不清窗口，只有新角度才清。

**新增接口的必要性应降到实际需要：**

| 候选项 | 最低修改量判断 |
|---|---|
| `TryTrigger()` | 建议有，返回是否接受即可；也可先在 App 中比较已有 `hcsr04_trigger_count` 前后值包装，保留驱动原签名。不要仅看 active，因为很快完成的测量也可能已变为空闲。 |
| `TakeResult()` | 建议用小包装集中上述消费规则，减少 App 出错；不是必须重构驱动的理由。必须在确认完成后先处理待滤波样本，再复制结果。仅“关中断读结构体”不能自动得到新滤波值。 |
| sequence counter | App 需要识别当前触发/点序号，但无需再建一套驱动计数器；已有 trigger_count 可用于触发标识。`measurement_count` 只统计有效测量，不能当所有完成事件的序号。 |
| timestamp | 非必要新增接口。现有 `hcsr04_last_measurement_ms` 仅在成功时更新，不可用来认领超时结果；如需点时间，在 App 封存时记录即可。 |
| 状态枚举 | 驱动已有内部状态以及 `hcsr04.h:25-44` 的诊断/结果枚举；直接复用，App 另有扫描状态即可。 |

原报告对“一致快照”的要求略重：在**唯一主循环拥有者、已完成、待样本已处理、尚未再触发**条件下，ISR 在 IDLE 不更新这份测量结果，读取可以保持稳定，不必为了多字段读取再扩大关中断区。现有 pending 样本交接和超时临界区应保留。

**2.2 DHT11 的安全空档只保护测距，不能保护 USART（高）。**

依据：`OLED-DHT11/Drivers/DHT11/dht11.c:85-95,104-140`。18 ms 起始低电平期间中断仍开启，真正全局屏蔽的是随后读 40 位的数毫秒；正常总占用接近二十多毫秒，不能把整段理解成“18 ms 关中断”。

115200、8N1 每字节约 `10/115200=86.8 µs`。若一条命令在数毫秒关中断窗口内连续到达，普通逐字节中断接收无法及时读 DR，会发生 overrun。每 2 秒才读一次 DHT 只能降低碰撞频率，不能消除它；“在两个扫描点之间读”也没有约束 PC 的发包时刻。

最低成本的本科毕设方案可以保留当前 DHT 读法，但必须**提前**落实 UART 错误后丢弃受损整行并重新同步、ACK 超时重发、START/STOP/SET 幂等，以及测得的命令响应上限；不能继续以“零 ORE、STOP 必在 40 ms 内完成”验收。若坚持任意时刻一次发送都不丢、零 ORE，则 DHT 关中断读法必须在联调前调整，不能等答辩前再观察。仅调 NVIC 优先级、增加环形缓冲、拆掉 18 ms HAL_Delay 都不能解决 PRIMASK 屏蔽 RX 的问题。

对其余影响应适度表述：避开活跃 ECHO 后，DHT 对 TIM2 的风险可控制；硬件 TIM3 PWM 会继续输出，不因 CPU 关中断停波。SysTick 不仅可能延迟，多次周期在屏蔽期间可能合并为一次待处理中断，使 HAL tick 少计时间；这不妨碍普通页面/去抖，但不能用它声称严格的墙钟时限。2 秒调度应记录 **last_attempt_tick**，成功时间另记；否则按最后成功时间重试会在传感器断线后连续占用主循环。

**2.3 固定 80–150 ms 不能覆盖首次定位和大角度跳转（中）。**

依据：`EncoderServoOLED/ReusableDrivers/Servo/servo.c:28-63` 只写 CCR、保存目标角，没有回读位置。SG90 的内部控制不能为本工程提供 MCU 可读的“已到位”信号。因此报告的 angle 应定义为**校准后的命令角/估计指向**，不可宣称是实时实测角。

另一个遗漏是 PWM 生效延迟：当前 HAL 的 `stm32f1xx_hal_tim.c:4235-4244` 在 PWM 配置时启用 CCR preload，更新比较值通常要等下一个周期边界，按 50 Hz 应计入最长约一个 20 ms 周期的等待。推荐从发命令时刻起计：**最多一个 PWM 周期 + 本次角差对应的实测运动时间 + 稳定余量**。最低实现可只分“启动/大跳转长等待”和“正常 5–10° 步进短等待”，不必增加编码器。这样足以支持静态场景本科展示；稳定时间仍应在实际负载和两个运动方向下校准。

**2.4 STOP、PUBLISH 与 UART 缓冲区的完成条件必须统一（高）。**

原报告第 11、17、21 节同时存在“结算正在进行的回波”“STOP 后无新点”“发送忙可丢弃/延后”“每点恰一条”，这些不能直接转成唯一实现。

建议最小约定：收到 STOP 后设 stop_requested，立即禁止新移角/新 TRIG；若有在途回波，只服务到完成或超时并消费，**丢弃尚未发布的当前角度批次**。已开始发送的串口行允许完整结束；随后发送 `$ACK,STOP`，此 ACK 之后不再发送 SCAN，直到下一次 START。无需把 STOP 写成一个会直接归中的舵机命令。

状态机还应补以下出口规则，不必增加大量状态：

| 触发条件 | 必须明确的行为 |
|---|---|
| Trigger 未被接受 | 留在可重试位置并保留错误处理出口，不能当作已启动进入 WAIT_ECHO；初始化失败不得无限重试。 |
| SET 在运行中 | 按报告推荐固定为 BUSY；避免同时保留“安全边界生效”的另一套语义。 |
| STOP 后立即 START | 先完成上一测量的清理；保留最近实际 TRIG 时间。不能以“首次触发”分支跳过跨 STOP/START 的声学间隔。 |
| PUBLISH 遇 TX busy | 明确选择有界待发一个点，或显式统计丢点。若保留“每点一条”，应保留该点等待发送，不能无声丢弃；等待期间仍处理 STOP。 |
| 中断发送进行中 | TX 缓冲保持不变直到 TxCplt；不能把下一点或 ACK 格式化到正在发送的同一数组。HAL 保存的是传入指针（`HC_SR04_ECHO/Drivers/STM32F1xx_HAL_Driver/Src/stm32f1xx_hal_uart.c:1311-1323`）。 |
| 完整 RX 行待处理 | ISR 必须冻结该行，或主循环先复制到独立解析缓冲再释放；“PC 等 ACK”并不能代替缓冲所有权规则。 |

## 3. 建议优化的问题

**HC 捕获与超时的边界说明。**原有换沿、16 位差值、首点/第二点/三点滤波算法可保持。CC1OF 作废仍值得补，但需要明确：若上升沿 ISR 迟到，下降沿在仍配置为上升沿时已经经过，可能直接漏掉下降沿，**不一定置 CC1OF**。所以 CC1OF 计数为零不能证明没有漏边沿。TIM2 捕获 ISR 应短，优先级高于串口业务性处理；DHT 不与回波重叠。

`hcsr04.c:296-327` 只在主循环 Process 中检查 40 ms，捕获回调不检查总截止时间。它是约 40 ms 加服务延迟的软超时；若主循环被阻塞，迟到边沿也可能先被 ISR 接受。最低方案是保证 WAIT_ECHO 期间主循环有界、无 DHT 读取和整屏刷新；无需为教学系统新加硬件定时超时。验收以“约 40 ms + 已测最大循环延迟”表述更准确。

**OLED 可用于最终答辩，但报告漏掉了运行时清屏的阻塞。**`EncoderServoOLED/ReusableDrivers/OLED/oled.c:177-191` 的 `OLED_Clear()` 会直接调用完整 `OLED_Update()`；页面切换若调用它，就绕过了分片预算。最低改法可在 App 用现有 `OLED_ClearLine()` 清 8 页显存，再绘制新页并继续 UpdateSlice，无需重写驱动。`ClearLine/DrawChar` 会把对应 `next_column` 重置为 0（194-226 行），不要每次循环都清行重画，否则前页不断重启发送、后页可能迟迟刷不到；只在数据改变/显示周期到期时重绘，并让分片发送持续推进。

保留现有 5×7 字形格式、补所需字符（尤其小数点及状态文字）最省改动。原报告建议的 MPU 工程字库是 8×16 格式，不能直接塞入当前读取 5 列字形的绘制函数；不应为补几个字母引入另一套渲染。软件 I2C 不检查 ACK 对固定接线演示可接受，不必把断线检测列为首版门槛。瞬间分片更新不保证屏幕像素级同步，保证的是最终完成一轮刷新后角度/距离来自同一数据快照；无需双 framebuffer。

第 10/15 节的“所有页面只读 ScanPoint”也宜收窄：角度与距离必须读同一封存点；温湿度页面应读环境缓存，通信页面应读协议状态，否则停止扫描、不再发布点以后，环境量和通信状态可能不再更新。协议中随点发送的环境量仍可在封存时复制，不必增加新的架构层。

**每角三次采样可保持，但应给展示速度一个实测预算。**以 17 点、每点 100 ms 稳定、两次样本间隔各 100 ms 为例，仅这些时间一趟就约 5.1 秒，另加回波、跨点间隔与重试；5° 步进的 33 点更慢。应标作逐点扫描图，避免承诺实时场景快照。三次样本也不是“同一时刻”的测量，适合静态目标；暂不因此改选跨角中值滤波。

## 4. 可以保持不变的设计

- **最终引脚与 Timer 参数**：第 1 节核对通过；不新增定时器，也不把 OLED 改成硬件 I2C。
- **HC 核心驱动**：适合先进入 FinalProject 的独立测距阶段。作为整机驱动交付前，要落实一次消费约束和 CC1OF 作废。保留输入捕获、换沿、40 ms 软超时、滤波和 FilterReset 的单一职责。
- **Servo→等待→HC→角度绑定**：对静态展示足够，条件是命令角标注正确、等待覆盖 PWM 生效和机械移动。无需为此增加位置反馈硬件。
- **App Scan 唯一调度者**：继续替代原 ServoScan 自主移角，按钮只发页面事件，ISR 不运行协议解析或显示逻辑。
- **PB12 轮询去抖、DHT 每约 2 秒、软件 I2C 分片显示**：均符合项目规模；DHT 不必为 18 ms 起始低脉冲立即重写成完整异步驱动。
- **目录与层次**：`Core + ReusableDrivers + App` 已足够；用户概述中的 `Drivers/HC_SR04/...` 与报告的 `ReusableDrivers/...` 属于命名差异，不影响架构。目录本身不增加运行期开销。只保留一套驱动、静态对象和少量固定缓冲，不增服务层/消息总线/RTOS。1024 字节 framebuffer 在芯片 20 KB SRAM 中可容纳，最终用链接 map 核对栈与总静态占用即可（[ST DS5319](https://www.st.com/resource/en/datasheet/stm32f103c8.pdf)）。

## 5. 当前最高优先级风险

**最需要提前作决定的是 DHT11 全局关中断与 USART1 异步命令的共存方式。**它已有可直接定位的代码依据，且会影响 STOP 是否可靠、报文是否完整和“零 ORE”是否可验收。原报告把它留作“若实测出问题再处理”不够，应在串口联调前明确选择重试容错，还是修改临界区以满足更严格响应要求。

**最先要在扫描开发中验证的是一测量一消费。**先用两个明显不同的固定角交替测量，并加入无回波、第五次才凑齐三样本、测量中 STOP 和立即再 START。核对角度归属、样本数、点序号；这些通过后再扩展连续扫角。这里不要求新造复杂接口。
